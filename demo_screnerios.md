Demo Scenarios and API Payloads
Use these JSON payloads in the FastAPI UI (http://127.0.0.1:8000/docs) to run your demo.

Scenario 1: Successful Tool Execution
Goal: Show the system correctly identifying the user's need, extracting all parameters, calling the correct tool, and formatting the response.

User Message: Can you make me some notes on the Water Cycle for my Environmental Science class?

Copy and paste this JSON into the request body:

{
  "user_id": "student-demo-123",
  "conversation_id": "conv-001",
  "message": "Can you make me some notes on the Water Cycle for my Environmental Science class?",
  "user_info": {
    "name": "Alex",
    "grade_level": "10",
    "learning_style_summary": "Prefers outlines and structured notes",
    "emotional_state_summary": "Focused and attentive",
    "mastery_level_summary": "Level 6: Good understanding"
  },
  "chat_history": [
    {
      "role": "user",
      "content": "Hi there!"
    },
    {
      "role": "assistant",
      "content": "Hello Alex! How can I help you today?"
    }
  ]
}

Expected Outcome: The orchestrator will call the note_maker_tool and return a friendly, formatted summary of the notes generated by the mock service.

Scenario 2: Handling Missing Parameters (Clarification)
Goal: Show the system's ability to handle an ambiguous request, identify missing parameters, and ask a clarifying question.

User Message: I want to make some flashcards.

Copy and paste this JSON into the request body:

{
  "user_id": "student-demo-123",
  "conversation_id": "conv-002",
  "message": "I want to make some flashcards.",
  "user_info": {
    "name": "Alex",
    "grade_level": "10",
    "learning_style_summary": "Visual learner",
    "emotional_state_summary": "Curious",
    "mastery_level_summary": "Level 5: Developing competence"
  },
  "chat_history": []
}

Expected Outcome: The orchestrator will identify that the topic, count, and difficulty parameters are missing for the flashcard_generator_tool and respond with a question like: "What topic would you like the flashcards to be about?"

Scenario 3: No Tool Match (Graceful Fallback)
Goal: Demonstrate that the system can handle general conversation that doesn't map to any specific tool.

User Message: Thanks, that was really helpful!

Copy and paste this JSON into the request body:

{
  "user_id": "student-demo-123",
  "conversation_id": "conv-003",
  "message": "Thanks, that was really helpful!",
  "user_info": {
    "name": "Alex",
    "grade_level": "10",
    "learning_style_summary": "Visual learner",
    "emotional_state_summary": "Pleased",
    "mastery_level_summary": "Level 5: Developing competence"
  },
  "chat_history": [
    {
        "role": "user",
        "content": "Can you explain photosynthesis?"
    },
    {
        "role": "assistant",
        "content": "Of course! Photosynthesis is the process..."
    }
  ]
}

Expected Outcome: The router will determine that no tool is appropriate and the system will return a polite, generic response like: "I can't directly answer that, but I can help with other educational tools. What would you like to do?"
